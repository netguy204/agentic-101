# Practice: the brief, for real

<!-- Chunk: docs/chunks/fluency_session_03 - Session 3 practice assignment -->

**About 55 minutes, spread across the week. Cap it at 90.**

You left the room with a delegation brief that has run twice on made-up
material. This week it runs on the real thing — the task it was written for,
when that task next comes round. That is work you were going to do by hand
anyway; the point is that some of this hour replaces some of that hour.

**Where you're heading:** by Session 4, your brief will have run on the real
task twice, you'll have changed one box between the runs, and you'll have
one sentence about what the second run caught that the first didn't. Session
4 takes that brief and asks what happens when it has to run every week.

---

## The time budget

| When | How long | What |
|---|---|---|
| When the task next comes round | 20 min | Run the brief on the real task — the loop, once |
| Later in the week, the next time round (or the next day, on the same material) | 20 min | Change one box, run it again |
| Once, before Session 4 | 10 min | One sentence: what the second run caught that the first didn't |
| Optional | 15 min | Brief an `out` entry and find the box you can't fill |
| | **50–65 min** | |

**If the second run didn't happen in the room** — the facilitator may have
let it go to the practice week — it is the first twenty minutes here, with
the change you already wrote, before anything on the real task.

---

## Before you use the real task: the gate

Same gate as Session 2's practice sheet, and it hasn't moved. **All four:**
you can tell a reasonable result from an unreasonable one and name the check
(your checkpoints box *is* this answer now); you're allowed to delegate the
task and send its data to the course model provider; it's draft or
preparation work, not a consequential decision about a person, money,
access or rights; and a person reviews the actual output and approves it
before anything is sent, published, or acted on outside the practice folder.
**It does, you decide.** Session 2's
[`PRACTICE.md`](../session_02_meeting_the_harness/PRACTICE.md) has the full
wording and the supplier-email example; read it again if any of the four
gives you pause.

And the same three honest options for your data: describe the shape and let
it invent; copy a small, real, non-sensitive extract into `~/course-practice`
only if you're authorized to send it to the provider; or use the task but
not the data. If you're unsure, ask whoever owns it — before, not after.

---

## 1. Run it on the real task (20 minutes, when it comes round)

The loop from Sessions 2 and 3, on the real thing:

1. `cd ~/course-practice`, `pwd`, and get the inputs your brief names into
   the folder — the real extract if the gate allows, a made-up version of
   the same shape if not.
2. `commit`, named **real run 1**.
3. `pi`. Send the Instruction box word for word, plus any Inputs fact that
   isn't in a file. Nothing else.
4. Read it: the boxes, the file, then your Checkpoints box, literally.
5. `commit`, named **after real run 1**, or `revert` if you didn't want to
   keep the local files.
6. **Keep the result as a draft** until the required person has reviewed
   it and approved anything that leaves the folder.

Then the question from exercise 3: *which box let me down?* Write the
change on the brief and the reason in one sentence — even if the answer is
"none, so I'm adding a checkpoint."

**If the real task doesn't come round this week,** run it on the made-up
material from the session again, or on a made-up version of the real
input. The loop is the practice; the real data is a bonus.

---

## 2. Change one box, run it again (20 minutes)

When the task next comes round — or the next day, on the same material,
after `revert` back to *real run 1*:

1. Make the one change you wrote down. One box.
2. `commit` before, `pi`, send the revised instruction, read it, apply the
   checkpoints, `commit` after.
3. Compare with the first run. Did the change do what you expected? If not,
   that's the sentence — and it's a more useful sentence than "yes".

**One box per run.** It feels slow and it is faster: a change and a run is
two minutes; three changes and a guess is a week of not knowing which one
mattered.

---

## 3. One sentence (10 minutes, before Session 4)

On the bottom of the brief, under the sentence from the session, write a
second one:

> **What the second run caught that the first didn't** — or, if the real
> task behaved differently from the made-up one, what the real task taught
> you that the room couldn't.

Bring it. Session 4 opens with the briefs and these sentences, and a room
full of "the real one turned out to need a fact I'd never have thought of"
is exactly the material it needs.

---

## Optional, if you want more

Pick one entry marked **out** on your inventory — one you honestly could not
check. Write a brief for it anyway, all four boxes, and notice which box you
cannot fill. It's nearly always the checkpoints box, and the *specific* way
you can't fill it is the exact distance between where your judgment ends and
where that task lives. Write one sentence about what you'd need to know to
fill it. Don't run it.

If you *can* fill all four boxes — it happens — move the entry to **not
sure** and bring it up in Session 6.

---

## Bring to Session 4

- **Your brief**, with both sentences at the bottom and any second
  checkpoint you added.
- **Your toil inventory**, with ticks against everything you've delegated
  and any entry you moved between `in`, `not sure` and `out`.
- **One sentence about what the second run caught**, or what the real task
  taught you. You'll be asked for it in the first ten minutes.

## If the week gets away from you

Run the brief once, on anything — the real task if it comes round, the
made-up material if not — and write the change you'd make. Twenty minutes.
Skip the rest without guilt. A brief that has run three times with one
named change beats one that has run once with a paragraph of intentions,
and Session 4 can work with the former.
